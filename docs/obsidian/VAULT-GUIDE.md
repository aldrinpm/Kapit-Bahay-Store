# Obsidian Vault Guide

Open the extracted project root as an Obsidian vault, or add it to an existing vault.

Suggested workflow:
- Use `PROJECT-MEMORY.md` as the concise project status and durable decision log.
- Use `docs/requirements/` for product scope and acceptance criteria.
- Use `docs/architecture/ADR/` for technical decisions.
- Use `docs/development/` for roadmap and testing.
- Link related notes with Obsidian wikilinks where useful, while keeping standard Markdown links usable outside Obsidian.

Do not let the vault become a second, contradictory source of truth. Update existing documents rather than creating duplicate notes for the same topic.
